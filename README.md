# tp75 多语言文案管理平台

一个本地小工具：把产品界面上的文案集中管起来。页面上先登记要支持的语言，再按模块维护一条条文案，每条文案给各个语言分别填译文；键写重了、译文太长、语言代码没登记过，保存时当场就会指出来。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`


## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5075>

端口固定为 `5075`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 顶栏右侧可以填当前操作者，填过之后浏览器会记住，保存文案时会记下是谁改的
2. 语言区列出当前登记的语言，可以看到语言代码、名称、是不是默认语言、是否启用，以及这条语言下已经填了多少条译文
3. 语言区底部可以新增语言，填上代码与名称即可；已有语言可以改名、设为默认、启用或停用、删除
4. 文案区顶部可以按模块筛选、可以按文案键或译文内容搜索，右上角刷新按钮重新拉取一次
5. 点新建文案，填上模块、文案键与各语言的译文就能存下来；列表里点编辑会把这条文案回填到表单，改动保存后列表立刻更新
6. 编辑表单右侧是参考译文区：点进某种语言的译文输入框，就按这格里已经写的内容，从全部已填译文里找出最接近的几条，给出文案键、模块、语言与译文原文，并标出接近程度；原文完全一致的排在最前面，接近程度相同的按文案键、语言稳定排序，同样的条件重复查询结果顺序不变
7. 参考区可以收窄范围：勾选“只看当前模块”后只在表单里这个模块中找；语言小签可以只保留某几种语言（一个都不勾表示不限语言）；“最多 N 条”可以指定候选上限，候选不够时按实际条数返回，不会报错
8. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上；删除语言与删除文案都会先确认

列表里每种语言单独占一列，空白的格子表示这条文案在这个语言下还没有译文，未登记的格子表示这条文案从来没有写过这种语言。

## 文案键与译文的约定

- 模块名用小写字母开头，后面可以跟数字与短横线，最长 30 个字符
- 文案键形如 `home.banner.title`，由小写字母、数字、下划线与短横线组成，用点号分段，最长 120 个字符；同一个模块下不允许出现重复的键
- 译文最长 200 个字符，允许留空，留空表示这条文案在这个语言下还没有翻译
- 译文里可以写 `{amount}`、`{count}`、`{minutes}` 这样的占位符，由前端在运行时替换成实际取值，平台上原样保存、不做任何处理
- 备注用来写这条文案出现的页面位置，最长 200 个字符
- 操作者名字随保存一起记在文案上，最长 40 个字符，留空按未署名记录

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "languages": [...], "entries": [...] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。

## 接口一览

| 方法   | 路径                   | 说明                                         |
| ------ | ---------------------- | -------------------------------------------- |
| GET    | /api/health            | 服务状态检查                                 |
| GET    | /api/languages         | 语言清单，附带每种语言已填译文条数           |
| POST   | /api/languages         | 新增语言                                     |
| PATCH  | /api/languages/:code   | 修改语言的名称、启用状态或默认标记           |
| DELETE | /api/languages/:code   | 删除语言                                     |
| GET    | /api/entries           | 文案列表，支持按模块与关键词筛选             |
| GET    | /api/entries/similar   | 按当前文本找最接近的几条已填译文，供编辑参考 |
| POST   | /api/entries           | 新增文案                                     |
| GET    | /api/entries/:id       | 查看单条文案                                 |
| PATCH  | /api/entries/:id       | 修改文案                                     |
| DELETE | /api/entries/:id       | 删除文案                                     |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。

`GET /api/entries/similar` 的查询参数：

| 参数             | 说明                                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------------ |
| `text`           | 当前输入框里的文本，按它与已填译文的接近程度排序，完全一致的排最前                                     |
| `module`         | 只在这个模块的文案里找，可选                                                                           |
| `languages`      | 只在这几种语言的译文里找，可重复或用逗号分隔；给了但都没登记过时按空结果处理，可选                     |
| `limit`          | 候选条数上限，默认 5、最大 50；给得不合法时回落默认值，候选不足时按实际条数返回，可选                  |
| `excludeEntry`   | 编辑时传入当前文案 id，配合 `excludeLanguage` 排除正在编辑的那一格本身，可选                           |
| `excludeLanguage`| 与 `excludeEntry` 一起排除“同一条文案的同一种语言”，这条文案的其它语言仍然作为跨语言参考，可选         |

返回 `{ "text": "...", "references": [{ "entryId", "module", "key", "language", "text", "score", "exact" }] }`，`score` 是 0 到 1 的接近程度，`exact` 为真表示原文完全一致。
